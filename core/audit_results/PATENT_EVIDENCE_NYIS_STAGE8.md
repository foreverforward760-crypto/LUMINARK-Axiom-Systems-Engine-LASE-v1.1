# NYIS Exploratory Analysis — Corrected Evidence Status

> **Correction notice (2026-11-26): This document is not patent evidence and does not establish predictive accuracy, a technical advantage over conventional methods, or patentability. No patent application has been filed based on this analysis. The previous title and conclusions overstated what the underlying data and calculations establish.**

## What this analysis actually contains

The historical NYIS audit output in this repository reports 24 hourly records, including stage counts, Witness Position calculations, and Observer Effect calculations. The associated 2026-04-28 balancing-authority datasets were generated by `core/generate_ba_datasets.py`.

That generator explicitly creates **synthetic** NSDT time-series patterns using programmed normal and crisis patterns with random variation. It does not retrieve NYISO operational telemetry. The generated NYIS CSV therefore must not be described as actual NYISO measurements or as an observed grid failure dataset.

The separate `core/validated_events.json` file contains descriptions of historical grid events and assigned NSDT signatures. The repository does not establish that those signatures were derived from raw, time-aligned telemetry or independently labeled by grid-domain experts. Their presence does not demonstrate model calibration or prospective validation.

## What the calculations show

The audit script applies hand-coded formulas to each row:

- Stage assignment is derived from the tension value using `int(tension / 11.11)`.
- Witness Position is derived from a fixed weighted formula and thresholds.
- The Observer Effect V-value is derived from fixed entropy, energy, and velocity expressions.
- The 1.35 multiplier is a configured model parameter applied when a rule condition is met.

These calculations show how the programmed rules behave on the supplied synthetic records. They do not show that the rules correctly detect real grid instability, identify hidden brittleness, improve interventions, or predict outages.

## Claims withdrawn

The following claims in the prior version are withdrawn because the repository does not provide adequate evidence for them:

- 100% detection of hidden brittleness cases versus 0% for conventional methods.
- A measured 35% reorganization improvement.
- A 300–18,000× speed advantage over conventional methods.
- A demonstrated reduction in repair iterations or improved governance effectiveness.
- That this analysis supports patent claims or survives a patent-eligibility review under 35 U.S.C. § 101.

The 1.35 multiplier is a programmed setting, not a measured 35% improvement. A code path that multiplies a value by 1.35 does not establish a real-world performance gain.

## What would be needed for a defensible validation study

A meaningful grid-domain validation would require, at minimum:

1. Provenance-documented, time-stamped operational telemetry from independent balancing authorities.
2. Expert-defined outcome labels and documented event windows.
3. A pre-registered evaluation protocol and separation of calibration data from held-out test data.
4. Comparisons against appropriate existing baselines using the same input data.
5. Measures such as precision, recall, false-alarm rate, lead time, calibration, and performance across operating conditions.
6. Independent review by qualified power-system engineers.

Until that work is completed, the engine should be described as an exploratory rule-based prototype. It should not be used to make grid-operations decisions.
